## What this domain owns

The trained recognition models, and the corpus of gesture samples they are trained from.

**One domain, two bounded contexts and two databases.** The DBML groups both under `AI` because both are
about the recognition model. In the domain map the trained model belongs to the Core and the samples
belong to Consent & Personal Data, because the rules that govern a sample are consent rules, not
recognition rules. Both groupings are right for what they are for — one is a diagram, the other is a
boundary.

## `ai_models` — PostgreSQL

**Purpose:** the version of the recognition model in use, and the provenance of every version that ever
produced a translation.

```sql
CREATE TABLE ai.ai_models (
  model_id          UUID          PRIMARY KEY DEFAULT gen_random_uuid(),
  version           VARCHAR(50)   NOT NULL UNIQUE,                -- 1.0.0, 1.1.0
  description       VARCHAR(255),

  trained_at        TIMESTAMPTZ   NOT NULL,
  trained_by        UUID          NOT NULL REFERENCES identity.users (user_id) ON DELETE RESTRICT,
  sign_language     sign_language NOT NULL DEFAULT 'LSC',

  sample_count      INTEGER       NOT NULL,
  sign_count        INTEGER       NOT NULL,
  accuracy          DECIMAL(5,4),                                 -- 0 … 1 on the test set

  storage_reference TEXT          NOT NULL,                       -- path to the published .tflite
  is_active         BOOLEAN       NOT NULL DEFAULT FALSE,

  created_at        TIMESTAMPTZ   NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_models_active  ON ai.ai_models (is_active);
CREATE INDEX idx_models_trained ON ai.ai_models (trained_at);
```

**Data dictionary:**

| Column | Meaning | Notes |
|--------|---------|-------|
| `version` | Semantic version of the model | Unique. It is what a user's history points at through `translations.model_id` |
| `trained_by` | The administrator or linguist who ran the training | `RESTRICT` — the provenance of a model is part of the model, and cannot be deleted while the model exists |
| `sample_count` / `sign_count` | How many samples trained it, how many distinct signs it recognizes | `sign_count` is what a sign publication check compares against (INV-018) |
| `accuracy` | Accuracy on the test set, 0…1 | ⚠️ **Not the confidence threshold.** Accuracy describes the model; the threshold decides whether a single recognition is shown. The threshold column does not exist — ALIGN-03 |
| `storage_reference` | Path to the published `.tflite` artifact | A `.tflite` extension suggests on-device inference, but **that decision has never been recorded**. A file extension is not a decision — see `02-domain/domain-map.md` § 5 |
| `is_active` | The model the app is currently serving | ⚠️ Only one may be true (INV-022); the plain index does not enforce it — `uq_single_active_model` does |

**Activation is a two-step transaction, not an update.** Setting a new model active must deactivate the
previous one in the same transaction. `uq_single_active_model` (a partial unique index on
`is_active = TRUE`, in [`../constraints.md`](../constraints.md)) is what guarantees the application
actually did it — without it, two devices translate with different versions and nobody can compare the
results.

## `gesture_samples` — MongoDB, owned by recognition-service

**Purpose:** the training corpus. **Not a table**: an independent MongoDB collection with **no foreign
keys into the relational model**. `sign_id`, `recorded_by` and `validated_by` are public identifiers the
application resolves, not references the database enforces.

```javascript
// db.gesture_samples — MongoDB 7
{
  sample_id:             UUID,        // _id
  sign_id:               UUID,        // → lexicon.sign_lexicon.sign_id — public identifier, no FK
  capture_session_id:    UUID,        // groups every take of one recording batch

  recorded_by:           UUID,        // → identity.users.user_id — the operator (admin/linguist)
  performed_by:          String,      // who physically performed the sign; may be an external collaborator

  consent_granted_at:    ISODate,     // required — Law 1581
  consent_terms_version: String,      // required — which authorization document was signed

  sample_type:           String,      // LANDMARKS (default) | VIDEO | IMAGE
  storage_reference:     String,      // object-storage path

  is_validated:          Boolean,     // only validated samples feed training
  validated_by:          UUID,        // nullable
  validated_at:          ISODate,     // nullable
  created_at:            ISODate
}

db.gesture_samples.createIndex({ sign_id: 1 },                  { name: "idx_samples_sign" });
db.gesture_samples.createIndex({ capture_session_id: 1 },       { name: "idx_samples_session" });
db.gesture_samples.createIndex({ sign_id: 1, is_validated: 1 }, { name: "idx_samples_trainable" });
```

**Why this collection is not a table.** A training sample's metadata changes every time the recognition
pipeline changes: today landmarks and a storage path, tomorrow frame rate, hand count, capture device,
extractor version. In the relational schema each of those is a migration. This is the one part of the
system whose schema is genuinely unstable, and it is the one part that is not relational.

**The cost is real and must be stated:** nothing prevents a sample pointing at a sign that no longer
exists. Consistency is the application's job. The benefit is that the collection evolves without
touching the PostgreSQL databases, and that it can be moved, dumped or destroyed as a unit — which matters for a
dataset governed by Law 1581.

**A JSON Schema validator replaces the `NOT NULL`s the relational model would have given for free.**
MongoDB will happily accept a sample with no consent evidence unless told otherwise, and a sample with
no consent evidence is, under Law 1581, an illegal record:

```javascript
db.createCollection("gesture_samples", {
  validator: { $jsonSchema: {
    bsonType: "object",
    required: ["sign_id", "capture_session_id", "recorded_by", "performed_by",
               "consent_granted_at", "consent_terms_version", "sample_type",
               "storage_reference", "is_validated", "created_at"],
    properties: {
      sample_type:  { enum: ["LANDMARKS", "VIDEO", "IMAGE"] },
      is_validated: { bsonType: "bool" },
      performed_by: { bsonType: "string", maxLength: 150 }
    }
  }},
  validationLevel: "strict",
  validationAction: "error"
});
```

**`capture_session_id` is the unit of discard, not the individual sample.** A recording batch is what a
linguist rejects and what a revoked authorization removes. That is why it is indexed and why it exists
at all.

## ⚠️ This collection holds biometric data of identified people

`performed_by` names the person and `consent_granted_at` proves their authorization. That is deliberate
— it is what makes a **withdrawn** authorization honorable, which anonymization makes impossible — but
it is the exact opposite of INV-010, which says a sample never carries anything re-identifying.

Two incompatible, individually defensible designs:

| | v1.0 domain model (INV-010) | v8 data model |
|---|---|---|
| Sample source | Harvested from end users while translating | Deliberate capture sessions run by a linguist |
| Identity | `AnonymousSubjectId`, irreversible pseudonym | `performed_by`, the performer's name |
| Consent | Implied by the account's terms acceptance | Signed per person, per document version |
| Revocation | Impossible to honor — the samples cannot be found | Delete every sample of that `capture_session_id` |

**One of the two has to go, and it is a team decision, not an editorial one** (ALIGN-02). Whichever way
it lands, two requirements hold either way: **encryption at rest is not optional** for this store and
its object storage, and a revocation must be executable in one operation.

## Invariants this domain enforces

| Invariant | Where it is enforced |
|-----------|----------------------|
| INV-008 — no sample without a valid consent grant | `consent_granted_at` and `consent_terms_version` are `required` in the validator |
| INV-022 — exactly one model is active | `uq_single_active_model` + `ON DELETE RESTRICT` on `translations.model_id` |
| INV-010 — samples are dissociated from identity | ⚠️ **Contradicted by this model, deliberately** — ALIGN-02 |
| INV-007 — a threshold decides what counts as a confirmed translation | ⚠️ **No column to read it from** — ALIGN-03 |
