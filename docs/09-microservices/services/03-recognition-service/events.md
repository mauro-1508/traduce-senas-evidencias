# Events — Recognition Service

> Asynchronous events over RabbitMQ: exchange `traduce.events` (topic), routing key `recognition.<EventName>`.
> Definitions and payloads: `02-domain/domain-events.md`. **The code publishes no event today**; everything below is the target.

---

## Events this service PUBLISHES

| Event | Routing key | When | Payload (key fields) | Consumers |
|-------|-------------|------|----------------------|-----------|
| `TranslationSessionStarted` | `recognition.TranslationSessionStarted` | The user turns translation mode on and the camera is ready | `{sessionId, userId, outputMode, modelVersion, startedAt}` | analytics |
| `TranslationProduced` | `recognition.TranslationProduced` | A sign is recognized above the threshold and delivered | `{sessionId, translationId, userId, gloss, text, confidence, outputMode, modelVersion, producedAt}` | analytics (counts), profile (achievement progress) |
| `RecognitionFailed` | `recognition.RecognitionFailed` | Low confidence, sign outside the vocabulary or engine error | `{sessionId, reason, confidence, threshold, occurredAt}` | analytics (problematic signs), profile (on-screen alert) |
| `TranslationSessionEnded` | `recognition.TranslationSessionEnded` | Translation mode turned off | `{sessionId, userId, endedAt, translationCount, durationSeconds}` | analytics |
| `TranslationSessionInterrupted` | `recognition.TranslationSessionInterrupted` | Camera denied, connection lost, engine error | `{sessionId, userId, reason, interruptedAt, translationCount}` | analytics, profile |
| `TranslationDeleted` | `recognition.TranslationDeleted` | The user deletes a history entry | `{translationId, sessionId, userId, deletedAt}` | analytics |
| `RecognitionModelTrained` | `recognition.RecognitionModelTrained` | A training run finishes and is registered | `{modelId, version, trainedBy, trainedAt, sampleCount, signCount, accuracy}` | iam (audit) |
| `RecognitionModelPublished` | `recognition.RecognitionModelPublished` | An administrator activates a model version | `{modelId, version, previousModelId, accuracy, storageReference, publishedAt}` | analytics, iam (audit), the app (downloads the artifact) |
| `GestureSampleCaptured` | `recognition.GestureSampleCaptured` | A sample is recorded in a capture session | `{sampleId, captureSessionId, signCode, sampleType, recordedBy, consentGrantedAt, consentTermsVersion, capturedAt}` | iam (compliance audit) |
| `GestureSampleValidated` | `recognition.GestureSampleValidated` | A linguist approves a sample | `{sampleId, validatedBy, validatedAt}` | the training pipeline (itself) |
| `CaptureSessionDiscarded` | `recognition.CaptureSessionDiscarded` | A batch is discarded or a collaborator withdraws authorization | `{captureSessionId, sampleCount, reason, discardedBy, discardedAt}` | iam (audit) |
| `TrainingSampleAnonymized` | `recognition.TrainingSampleAnonymized` | A sample is persisted under an irreversible pseudonym (only if INV-010 is kept, ALIGN-02) | `{sampleId, anonymousSubjectId, gloss, anonymizedAt}` | iam (audit) |

`TranslationProduced` carries the gloss and the text, **never the video or the sample** (INV-008).

### Session events and the data model

`TranslationSession` has no table (ALIGN-01). The session events are emitted from the runtime session of the service; the
`sessionId` is generated by recognition and is not persisted. This must be resolved with the data team.

## Events this service CONSUMES

| Event | Published by | What recognition does |
|-------|--------------|-----------------------|
| `ConsentGranted` | iam | Enables keeping samples for that user |
| `ConsentRevoked` | iam | Stops keeping samples (translation keeps working) and discards the capture sessions of that collaborator (emits `CaptureSessionDiscarded`) |
| `AccountDeletionRequested` | iam | Deletes the user's `translations` and `translation_signs`, and the samples recorded by or for them; then reports completion |
| `SignPublished` | lexicon | Adds the sign `code` to the local catalog of recognizable signs |
| `SignWithdrawn` | lexicon | Marks the code as no longer recognizable |

All handlers are idempotent (processed `eventId`s are stored). Queue: `recognition.main`, bound to `iam.Consent*`,
`iam.AccountDeletionRequested`, `lexicon.Sign*`.

---

## Delivery guarantees

| Guarantee | Value | Implication |
|-----------|-------|-------------|
| At-least-once | Yes | Consumers are idempotent (`eventId`) |
| At-most-once | No | |
| Exactly-once | No | |

Publishing goes through a transactional outbox in the `recognition` database.

## Error handling

- **Dead Letter Queue:** `recognition.main.dlq`
- **Retries:** 3 to 5 with exponential backoff, 7-day retention
- **Alerts:** any message in the DLQ. A failed `ConsentRevoked` or `AccountDeletionRequested` is a legal risk and has priority
